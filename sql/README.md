# DB 설정

이 저장소에는 마이그레이션 도구가 없습니다. 아래 SQL 파일을 실행하면 됩니다.
모든 파일은 여러 번 실행해도 안전합니다 (중복 생성·중복 등록되지 않습니다).

상황에 따라 둘 중 하나를 고르세요.

| 상황 | 실행할 파일 |
| --- | --- |
| **A. 이 사이트 전용 DB를 쓴다** | `001` → `002` |
| **B. 다른 서비스와 DB를 함께 쓴다** | `003` → `002` (+ 연결 문자열 수정) |

---

## A. 전용 DB를 쓰는 경우

| 파일 | 하는 일 | 안 하면 |
| --- | --- | --- |
| `001_quote_requests.sql` | 견적 문의 접수 테이블 생성 | 견적 폼이 접수되지 않음 |
| `002_seed_projects.sql` | 시공사례 18건 등록 | 시공사례가 비어 있음 |

```bash
export DATABASE_URL="여기에 연결 문자열"
pnpm db:setup
```

또는 DB 제공업체(Neon, Supabase, Vercel Postgres)의 **웹 SQL 편집기**에 파일 내용을
그대로 붙여넣어도 됩니다. 설치할 것이 없습니다.

---

## B. 다른 서비스와 DB를 함께 쓰는 경우

하나의 PostgreSQL 안에 여러 서비스를 두면서 데이터가 섞이지 않게 하려면
**전용 스키마**를 씁니다. 모든 테이블이 `public` 이 아닌 `nmsolution` 스키마에
들어가므로, 다른 서비스에 같은 이름의 테이블(`projects` 등)이 있어도 충돌하지 않습니다.

### 1) 스키마와 테이블 만들기

`003_shared_project_schema.sql` 을 실행합니다. 인증·콘텐츠·시공사례·견적문의
테이블 7개가 모두 `nmsolution` 스키마 안에 생성됩니다.

### 2) 시공사례 등록

SQL 편집기에서 아래를 먼저 실행한 뒤 `002_seed_projects.sql` 을 실행합니다.

```sql
SET search_path TO nmsolution;
```

### 3) 연결 문자열에 search_path 추가 ← 빠뜨리기 쉬움

앱이 자기 스키마만 보도록 `DATABASE_URL` 뒤에 붙입니다.

```
?options=-c%20search_path%3Dnmsolution
```

예시:

```
postgres://user:pw@host:5432/dbname?options=-c%20search_path%3Dnmsolution
```

이미 `?` 로 시작하는 값이 있으면 `?` 대신 `&` 를 씁니다.
**앱 코드는 수정할 필요가 없습니다.**

> Supabase 를 쓴다면 서버리스 환경에서는 연결 풀링 주소(6543 포트, `pooler`)를
> 쓰는 편이 안정적입니다.

### 나중에 분리하기

전용 DB로 옮기고 싶어지면 두 줄이면 됩니다.

```bash
pg_dump "$DATABASE_URL" --schema=nmsolution > nmsolution.sql
psql "$NEW_DATABASE_URL" -f nmsolution.sql
```

다른 서비스 데이터는 덤프에 전혀 포함되지 않습니다.

---

## 실행 후 관리자에서 할 일

1. **사이트 설정 → 시공사례 노출**을 켭니다. 그래야 홈에 시공사례 섹션이 나옵니다.
2. **시공사례**에서 각 건의 **위치 · 연도 · 소요기간**을 채웁니다.
   실제 정보를 몰라 비워 두었습니다. 공장 담당자가 업체를 고를 때 가장 많이 보는
   항목이므로 채워 두는 편이 좋습니다.
3. 새 DB로 옮긴 경우 `/admin` 에서 **관리자 계정을 다시 만듭니다** (최초 1회만 가능).

접수된 견적 문의는 **관리자 → 견적 문의**에서 확인합니다.

## 검증 내역

PostgreSQL 16 에서 실제로 실행해 확인했습니다.

**A안**

- `001` 실행 후 `quote_requests` 테이블과 인덱스 2개 생성, 재실행 시 오류 없음
- `002` 실행 후 `INSERT 0 18`, 재실행 시 `INSERT 0 0`
- 앱 연결 후 시공사례 18건이 6개 공종 필터와 함께 표시, 견적 폼 제출 저장 확인

**B안** — `public` 에 같은 이름의 `projects` 테이블이 있는 DB에서 검증

- `003` 실행 후 테이블 7개가 모두 `nmsolution` 에만 생성됨
- 시공사례 18건이 `nmsolution.projects` 에만 등록되고 `public.projects` 는 그대로
- `search_path` 를 넣은 연결 문자열만으로 **앱 코드 수정 없이** 동작
- 앱에서 견적 폼을 제출한 뒤에도 `public` 테이블 수는 그대로(2개), 다른 서비스
  데이터 변화 없음
- `pg_dump --schema=nmsolution` 결과에 다른 서비스 데이터 0건, 새 DB로 복원해
  시공사례 18건 · 견적문의 · 테이블 7개가 그대로 살아나는 것까지 확인
